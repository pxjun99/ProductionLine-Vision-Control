# Mega 2560 V7 · 센서·분류·긴급 정지

| 장비 | 신호 핀 | 기능 |
|---|---|---|
| 컨베이어 드라이버 | PUL D5 / DIR D6 | 반주기 100µs, Timer3 출력 |
| SZH-LD088 | DIN D7 | 흰색 조명 독립 켜기·끄기 |
| DHT11 | DATA D30 | 실제 온도·습도, 약 2초 간격 측정 |
| MQ9 모듈 | AO A0 | 0~1023 아날로그 원시값. 농도·ppm 측정 아님 |
| 위치 제어 서보 | 신호 D11 | 평소 0°, 불량 분류 시 55° |
| 긴급 정지 NC 접점 | D12–GND | 평소 닫힘 LOW, 누름/단선 시 HIGH 정지 잠금 |
| 부저 | D8 | 경보 시 200Hz 0.5초 울림/0.5초 쉼 반복 |
| 빨간 LED (220Ω) | D40 | 경보 시 깜빡임, YOLO 불량 판정 시 2초 켜짐 |
| 초록 LED (220Ω) | D42 | YOLO 정상 판정 시 2초 켜짐 |

각 장비에 맞는 전원을 사용하고 Mega와 GND를 공통 연결한다. 서보는 사양에 맞는 별도 전원을 사용한다. D7은 데이터 핀이며 LED 전원을 공급하는 핀이 아니다. LED DIN에 330Ω 직렬 저항을 사용한다. D12에는 접점만 연결한다.

**실제 긴급 정지는 모터 구동 전원을 차단하는 별도 회로와 함께 구성해야 한다. 이 펌웨어는 안전 인증된 긴급 정지 제어기가 아니다.**

## 실행

1. 기존 서버·사용자·관리자 앱을 종료한 후 최신 실행 파일로 다시 실행한다.
2. 사용자 화면에서 **아두이노 설정·업로드 → COM 선택 → 업로드·연결**을 누른다. 보드의 기존 코드가 V7로 바뀐다. 실제 보드에 자동 업로드하지는 않았다.
3. 업로드 후 벨트 정지·조명 켜짐으로 시작한다. NC 접점이 정상으로 닫혀 있어야 한다.
4. 온습도·가스·벨트·서보·긴급 정지 상태가 사용자와 관리자 전체 현황/상세 화면에 표시된다. 서버는 최근 10분 센서 이력을 메모리에 보관하며 영구 저장하지 않는다.
5. **기본속도 이동(ms)** 기본 2000, **55° 유지(ms)** 기본 1000이다. 실제 이동 시간을 측정해 조정하고 **불량 자동 분류**를 체크한다. 초기에는 꺼져 있다.
6. **벨트 구동 → 검사 시작**. 정상 제품은 통과하고 불량 판정 제품만 55°로 분류한다. 인식 때문에 매번 벨트를 멈추지 않는다.

분류 위치에 통과 센서가 없으므로 0° 복귀는 실제 통과 감지가 아닌 **설정한 유지 시간** 기준이다. 제품 사이에 충분한 간격이 필요하다. 겹치는 분류 예약과 늦은 예약은 거부하며 자동 분류 중 오류가 발생하면 벨트를 정지한다. 프레임 수신 이후 추론·시리얼 대기 시간을 빼서 예약한다. 카메라 지연과 실제 속도는 현장에서 보정한다. 전체 추론 시간이 이동 시간보다 길면 속도·검사 위치 또는 모델 구성을 조정해야 한다.

## 긴급 정지·센서

- NC 접점이 열리면 PC와 관계없이 핀 변경 인터럽트가 벨트 펄스를 정지한다. 분류 예약 취소·서보 신호 해제.
- 버튼을 원상복귀해도 재출발하지 않는다. **버튼 해제 → 긴급 정지 잠금 해제 → 벨트 구동**으로 수동 재시작한다.
- PC 명령이 3초 동안 없으면 벨트 정지·분류 취소. 관리자 화면은 5초 이상 수신이 없으면 현재 상태 미확인으로 표시한다.
- DHT11 실패는 측정 실패로 표시한다. MQ9 A0 입력은 처음부터 표시하되 첫 60초는 초기 예열 중으로 표시한다. 이는 충분한 예열·교정을 보장하지 않으며 제조사 요구 조건을 별도로 확인한다.
- MQ9 AO를 A0에 연결한다. D8은 가스 입력이 아니라 부저 출력이다. 원시 입력값은 농도(ppm)가 아니다.
- **경보**: 가스 A0 600 이상 또는 온도 31℃ 이상이면 빨간 LED 깜빡임 + 부저. 가스 580 미만이면서 온도 30.5℃ 미만이 되면 해제된다. 긴급 정지 버튼은 벨트만 멈추고 경보는 끄지 않는다. PC 미연결 때도 아두이노가 2초마다 온습도를 직접 읽어 경보를 판단한다(PC 연결 중에는 STATUS 요청 때 읽음).

## 시리얼 · 9600 baud · 줄바꿈

| 명령 | 응답/동작 |
|---|---|
| HELLO | PL_CONVEYOR_PUL_DIR_V7 STOPPED 또는 RUNNING |
| RUN / STOP / PING | RUNNING 또는 STOPPED |
| STATUS | HW + 실제 측정·장비 상태 JSON. `emergencySwitchReady`(버튼 원위치 후 0.2초 지나 잠금 해제 가능) 포함 |

## 라이브러리·확인 범위

공식 [Adafruit NeoPixel 1.12.5](https://github.com/adafruit/Adafruit_NeoPixel/tree/1.12.5), [Adafruit DHT 1.4.6](https://github.com/adafruit/DHT-sensor-library/tree/1.4.6), [Arduino Servo 1.3.0](https://github.com/arduino-libraries/Servo/tree/1.3.0) 소스와 라이선스를 포함했다. IDE 업로드 시 이 폴더 전체를 유지한다. 앱 도구도 하위 폴더까지 복사한다.

Mega 2560 대상 컴파일과 모의 통신·시간·긴급 정지 검사를 수행했다. 실제 모터·배선·센서·분류 타이밍은 현장에서 확인해야 한다.

## 분류 시간 확장
이동 대기와 55° 유지 시간을 각각 최대 60,000ms까지 설정할 수 있다. 기본값 2000ms/1000ms는 유지한다. 10초 이동·5초 유지를 넘겨 사용하려면 최신 V7를 다시 업로드해야 한다. 기존 V4 연결은 지원하되 지원하지 않는 긴 시간은 전송 전에 업로드 안내로 차단한다.

## 모든 제품 인식 후 시간 설정 가속
정상·불량·판정 불가를 포함해 휴대폰 제품이 새로 인식되고 벨트가 구동 중이면 반주기 100µs에서 50µs로 2배 가속한다. 작업자 화면의 가속 유지 시간(초)을 0.5~60초로 설정한다(기본 3초). 설정 시간 뒤 100µs로 복귀한다. 같은 제품 ID의 중복 명령은 무시하고, 새로운 제품은 그 시점의 설정값으로 시간을 다시 센다. 벨트 정지·긴급 정지·통신 타임아웃은 가속을 즉시 취소하며 인식만으로 정지 벨트를 출발시키지 않는다.
불량 자동 분류 시 PRODUCT 명령 하나로 분류와 가속을 함께 예약한다. 기본속도 이동(ms)은 100µs 속도에서 검사 위치→분류 위치까지 걸리는 시간을 입력한다. 펄스 속도 변경 이력과 카메라 프레임 경과 시간을 반영한 이동량으로 분류 시점을 계산한다. 55° 유지 시간은 실제 경과 시간이다. 엔코더 피드백은 없으므로 실제 미끄러짐·카메라 지연·서보 반응과 제품 간격은 현장에서 보정한다. 유지 중 다음 정상품이 도착하지 않도록 간격을 확보한다.
명령: PRODUCT 제품ID 프레임경과ms 기본속도이동ms 유지ms 분류여부(0/1) 가속유지ms. 응답 PRODUCT_OK 제품ID.

작업자 화면에서 가속 유지 시간(초)을 직접 변경하거나, 관리자 원격 운영 화면에서 시간을 입력하고 가속 시간 적용을 누른다. 다음 제품 인식부터 적용하며 이미 진행 중인 가속 시간을 소급 변경하지 않는다. 앱 재실행 시 기본값 3초로 시작한다. 기존 V6 보드 연결 시 기존 1.25배/3초로 동작하므로 새 기능은 V7 업로드 후 사용한다.

## 통신 오류 확인 · 2026-10-21
온습도 DHT11 읽기는 STATUS 명령 전체를 수신한 후 응답 전에 실행한다. 수신 도중 백그라운드 DHT 읽기로 AVR 인터럽트가 중단되는 구간을 피하기 위한 변경이다. 새 앱은 오류에 요청 명령과 전송 내용을 표시하며, 새 보드는 UNKNOWN_COMMAND에 실제 수신 바이트(RXHEX)를 포함한다. 통신 오류를 무시하거나 제품 명령을 자동 재전송하지 않는다. 이 변경이 현장 오류의 실제 원인을 확정하는 것은 아니다.
적용: 앱 재실행 → 아두이노 설정·업로드 → COM3 → 업로드·연결. 재발하면 요청/전송/RXHEX가 포함된 전체 오류 내용을 확인한다. D11 분류 각도55도, 약2배 가속 및 설정 시간은 유지한다.
